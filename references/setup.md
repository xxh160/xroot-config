# 安装与迁移

适用于安装、迁移、软链接和依赖调整任务。具体配置和目标路径应从相关子目录源码、注释及应用约定中确认，本文件不维护应用清单。

1. 先检查系统、架构、仓库实际路径、可用包管理器，以及现有软件、版本管理器、配置与软链接。尊重环境变量覆盖的路径，不假设用户名或机器目录。
2. 阅读相关子目录入口、配置源码和就近注释，确认启用的功能。按需查阅对应版本的官方说明；不要凭文件名或旧文档推断行为。
3. 只补齐任务实际需要的依赖，优先复用已有运行环境和版本管理器。不要默认某一种包管理器，也不要重复安装同一工具。
4. 创建软链接前确认源存在。正确链接跳过；已有文件、目录或其他链接先记录并备份，再替换。保留恢复路径，不以空配置覆盖原文件。
5. 机器专属设置与通用配置分开处理；优先使用可移植的变量和环境检测。不要将运行时下载目录、缓存、凭据和历史记录纳入仓库。
6. 按相关子目录规则验证；命令、依赖、配置路径、备份/恢复方式及副作用记录在本机临时操作目录，规则见 [change-workflow.md](change-workflow.md)。不要提交机器部署记录。

## 反查本机指向本仓库的软链接

在仓库目录内执行以下只读命令。仓库路径由 Git 获取，不依赖用户名或固定安装位置：

```sh
repo="$(git rev-parse --show-toplevel)"
find "$HOME" -type l \
  \( -lname "$repo" -o -lname "$repo/*" \) \
  -exec ls -ld {} + 2>/dev/null
```

结果同时显示软链接及目标，包含指向仓库内文件或目录的链接。扫描范围是当前用户主目录，不跟随目录软链接；只匹配目标写成绝对路径的链接。没有匹配不代表不存在相对路径链接，且权限错误已隐藏；需要完整审计时另行解析相对目标并检查访问失败。
