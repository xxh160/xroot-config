# 技术教学与源码讲解

帮助学习者建立能够复述、推演和验证的心智模型。按读者建立理解的顺序组织讲解。

## 先建立整体，再沿一个案例深入

1. 交代系统要解决的问题、问题产生的原因、约束与核心设计思想。用关键组件的职责、边界与协作关系搭起整体架构，说明端到端的控制流、数据流和关键状态的归属。
2. 选一个有代表性的场景，从输入走到输出。沿同一条执行链路交代每个关键环节由谁触发、接收什么、做了什么、状态如何变化、结果交给谁。引入新概念时先说明它在链路中的位置。需要解释异常或分支时，从主线上的分叉点展开。
3. 让图和文字在对应段落配合。用架构图展示职责和边界，用时序图或链路图展示执行顺序，用状态图展示生命周期与分支。选能讲清当前机制的图，标明箭头表示调用、数据传递还是状态转换。局部机制复杂时补一张细节图，讲完回到整体链路。

## 用因果关系和源码解释机制

- 从目标和约束出发，讲清问题为何出现、直观方案在哪个约束下不足、当前机制如何解决问题。交代机制依赖的前提、需要维持的不变量、前提失效时的行为，以及付出的代价为何在当前场景可接受。
- 讲真实代码时，先提出机制，再用已核实的关键源码支撑它。沿调用关系确认实际的注册、触发和执行位置。给出可点击的精确行号链接，远程仓库优先链接到固定 commit。说明该行做了什么，以及这个行为怎样落实前面讲的机制。
- 区分从源码证实的行为、基于实现的推断与尚未验证的设计意图。源码不可用时，明确哪些行为待验证。

## 让模型能用于新场景

完整讲解结束时，选一个有意义的变化，例如关键步骤失败或输入条件改变。沿刚建立的模型推演控制流、状态和输出的变化，并指出在哪里可以验证。默认把讲解讲完整，根据理解需要或用户要求加入互动。局部追问直接回答，并在有助于理解时指出它在已有模型中的位置。
