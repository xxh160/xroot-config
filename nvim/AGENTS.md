# Neovim

遵循上级规则。此处说明架构与维护入口；选项值、快捷键和功能细节以源码及就近注释为准。

## 结构与职责

| 路径 | 职责 |
|---|---|
| `init.lua` | 唯一启动编排入口：依次加载基础选项、基础按键、诊断、插件系统、主题。 |
| `lua/options.lua` | 编辑器选项及运行环境适配，不负责声明插件。 |
| `lua/keymaps.lua` | 基础按键与 leader，在插件初始化前加载。 |
| `lua/lsp.lua` | Neovim 原生诊断样式与相关高亮，不负责安装语言服务。 |
| `lua/lazyn.lua` | lazy.nvim 引导和插件声明；负责依赖、加载时机、构建及配置回调。 |
| `lua/theme.lua` | 选择并应用主题，在插件系统初始化之后执行。 |
| `lua/plugins/` | 按插件组织的配置模块，由声明中的回调或显式 require 加载，不是自动扫描目录。 |
| `docs/` | 按需读取的维护方法，不复制配置参数清单。 |

典型依赖：`init.lua` → `lazyn.lua` 的声明/回调 → `lua/plugins/<模块>.lua`。语言服务由插件配置层组织，通用诊断外观留在原生配置层。改动前沿真实 require 和回调确认影响范围；存在文件不代表它已生效。

## Lua 与加载约定

- 适配 Neovim 的 LuaJIT/Lua 5.1 环境，不直接采用独立新版 Lua 才支持的语法。
- 普通模块使用局部变量；需要返回能力时使用模块返回值。只有编辑器回调确实需要时才暴露全局入口。
- leader 在插件加载前定义；主题依赖的插件先加载；使用插件 API 前确认加载时机与依赖声明。
- 自动命令使用具名、可重复创建的 augroup；缓冲区功能按需使用 buffer-local 映射。
- 修改接口时核对当前 Neovim 与已安装插件的版本。兼容处理、加载顺序的理由写在对应源码旁，不在这里复制实现。

## 验证入口

按改动范围读取 [docs/validation.md](docs/validation.md)：

- 纯文档：检查链接与 `git diff --check`。
- Lua 配置：语法检查、加载仓库配置启动、查看消息与相关健康检查。
- 插件、语言服务、格式化或按键：在上述基础上做对应功能验证。

本目录没有统一测试框架；无界面加载不代表真实界面交互已验证。不要为验证自动同步或升级全部插件。
