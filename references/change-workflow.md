# 修改、验证与机器操作

## 修改

- 先查看 Git 状态和相关差异，理解当前行为，再做最小范围修改。
- 配置行为、按键含义、特殊兼容处理及取舍写在对应源码旁的注释中。避免注释复述显然的语法；行为变化时同步更新注释。
- 根文档只保存跨应用规则；复杂子目录可设置短 `AGENTS.md`，提供源码导航与局部约束。较长专题再拆到该子目录，不把实现细节提升到外层。
- 不根据个人偏好替换用户已经选择的工具或删除功能。

## 通用代码风格

- 沿用修改位置的缩进、命名和引号约定，不为小改动重排整份配置；没有统一格式化设置时，不新增格式强制规则。
- 使用清晰命名和小范围职责；注释解释不明显的理由、兼容条件和约束，不逐句翻译代码。
- 更改目录职责、入口或验证方法时同步维护局部指南；引用路径或模块，不依赖易过期的行号。
- 各语言或应用专属约定放在相应子目录，不提升到通用层。

## 验证

- 使用实际生效配置验证；不要把跳过用户配置的启动结果当作通过。
- 按任务选择语法检查、真实启动及相关功能检查。隔离临时测试，避免影响现有会话；只清理自己创建的测试文件和进程。
- 区分配置可解析、进程可启动、功能可用和界面/按键已验证。无界面检查不能证明真实界面交互正常。
- 向用户说明实际检查结果和未验证部分，不以“全部正常”概括有限检查。

## 区分源码变更与机器操作

- **仓库源码变更**：由 Git 差异和提交历史记录，不额外维护变更流水账或 operations 日志。
- **在机器上应用配置**：安装/卸载依赖、修改环境、迁移文件或建立软链接前，在本机临时目录建立本次操作目录，记录命令、结果、失败重试、备份位置、恢复方式及副作用。应用后的验证输出也放在这里。
- 临时目录使用系统提供的位置，例如 `mktemp -d "${TMPDIR:-/tmp}/dotfiles-XXXXXXXX"`；向用户告知实际目录。临时目录可能被系统清理，长期保留的备份另选用户认可的位置。
- 不把机器操作记录、测试输出和备份放入 Git 跟踪范围。若任务明确需要存放在仓库内，先确认所在目录已被 `.gitignore` 忽略。
- 命令和输出不得泄露凭据。排查当前配置行为回到源码，不依赖某台机器的历史操作日志。
